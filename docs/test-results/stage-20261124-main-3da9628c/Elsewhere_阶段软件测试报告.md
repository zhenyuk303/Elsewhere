注册、密码登录和足迹相册达成本阶段计划的验收目标。E01 注册返回 `201`，使用注册响应发放的**同一个**会话访问 `/api/auth/me` 返回 `200`，账号名和新账号 ID 一致。I02 和 I03 均使用真实、独立的 MySQL，不以早期 H2 试跑代替正式验收。

**最值得关注：密码登录后整页刷新会返回登录页。** I03 删除足迹后，刷新没有直接回到相册。重新登录、进入足迹并筛选安徽后，上传记录仍然消失，项目内置的安徽照片仍在。H2 和 MySQL 的浏览器试跑均出现这个现象。源码中页面启动时恢复用户的分支由 OAuth 成功标记触发；若产品要求密码登录刷新后保持登录，应把它单独列为回归用例。本次 I03 验收的是删除结果在刷新后仍然成立；页面不能直接留在相册的差异保留在记录中。

## 黑盒测试：34 个通过

- **E01–E10｜等价类。** 登录状态和落库分别检查。新账号与会话各新增一条；非法输入返回 `400` 且两者都不新增；重复用户名返回 `409`，库中只保留原账号，原会话仍可用。
- **B01–B13｜边界值。** 用户名严格按计划由 `q` 拼成，密码用 `Aa1!` 加 `a` 补足；通过清理合成账号隔离每例，没有用后缀改变长度。B10–B13 独立执行，与 E03/E04/E07/E08 的对应关系保留在结果表。
- **C01–C03｜因果图。** 正确密码获会话；错误密码或账号不存在都返回 `401`、没有会话。“账号不存在但密码匹配”违背 `C2 → C1`，不属于可执行用例，也不是测试失败。
- **D01–D08｜判定表。** 先跑化简规则代表 D01、D02、D03、D05，再跑 D04、D06、D07、D08。仅三项都真时返回 `201` 并建立会话；其余均 `400`，不创建账号或会话，未限定多项错误的报错顺序。
