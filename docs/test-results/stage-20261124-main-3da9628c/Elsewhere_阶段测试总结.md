# Elsewhere 阶段测试总结

**执行日期：** 2026 年 11 月 24 日（北京时间）  
**测试基线：** `main @ 3da9628c`（`3da9628c822eea917f298d397558db54d508a7ee`）  
**计划：** [`Elsewhere 阶段软件测试计划`](Elsewhere_阶段软件测试计划.docx)

## 结论

阶段记录共统计 **45 个可执行用例通过、0 失败、0 阻塞、0 未执行**；另有 1 条因果图规则因约束不可构造，不计入执行用例。

**验收边界：I03 删除持久性有证据；刷新后保持认证并直接留在相册未通过，也未验收。** 密码登录后刷新会返回登录页，因此 I03 删除后的消失状态是在重新登录、重新进入相册并筛选安徽后确认。此结果支持“删除记录在刷新和重新登录后仍不存在”，不支持“刷新时保留认证状态并直接回到相册”。

## 执行范围与数字

按计划覆盖注册、密码登录与足迹相册，使用黑盒、白盒和集成测试。正式环境为 Windows 11、真实 MySQL 8.4.11 和 Codex 内置浏览器；I02、I03 使用独立 MySQL，I03 连接真实前后端。基线副本为指定提交；未改业务代码或原计划。

| 白盒：逻辑覆盖、基本路径 | L01–L04、P01–P04 | 8 通过 |

另有“账号不存在但密码匹配”规则 1 条。它违反 `C2 → C1`（密码匹配蕴含账号存在）的约束，没有可构造输入，故标为不适用，而非失败或未执行。

\* **I03 通过的证据范围是删除持久性：** 删除后刷新返回登录页；重新登录后确认上传照片不再出现，项目内置安徽照片仍在；MySQL 中该账号的安徽／合肥新增记录为 0。刷新后仍保持认证并直接显示相册不是本次通过项。

## 主要发现与下一步

注册链路覆盖成功、格式无效、重复账号和协议未同意等情况；成功注册发放的同一会话可访问 `/api/auth/me`，无效输入不新增账号或会话。密码登录的正确凭据成功，错误密码与不存在账号均拒绝且不发放会话。

I02 在真实后端和独立 MySQL 上完成创建、按 ID 读取照片与元数据、删除及删除后查询不到记录。I03 进一步验证浏览器中的上传、退出重登后读回同一张可解码照片、删除后重登确认记录消失。

**建议：** 若产品要求密码登录后刷新仍留在相册，新增独立回归验收项，要求刷新后不出现登录页且相册可直接读取；该项通过后再更新验收结论。删除持久性继续按现有的删除、刷新、重新登录、复查记录流程留证。其余 45 项可按逐用例结果表和证据日志复查。
