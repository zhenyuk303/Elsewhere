# 省份手写标识设计

## 意图

让登录页右侧轮播图中的省份名称使用现有毛笔字素材，强化视觉风格，同时保持每张轮播图与其省份名称严格对应。

## 目标

- 从工作区同级 `province/` 中的 17 张双省 PNG 生成 34 张独立透明 PNG。
- 仅保留原图中的毛笔字和拼音，去除粉色网格、外框与黑色分隔区。
- 将保留下来的黑色内容转换为白色，保留原始笔触细节和拼音排版。
- 在轮播图左下角用手写标识替换当前英文省名，并移除现有两位编号。
- 桌面端与窄屏布局都不遮挡右下角轮播计数器。

## 非目标

- 不修改省份照片、轮播顺序或轮播动画时序。
- 不重新设计、重绘或用生成式模型改写毛笔字。
- 不改变登录、注册或后端认证逻辑。
- 不在页面运行时进行 Canvas 抠图。

## 约束

- 原始素材位于 Git 仓库外层，不能作为线上运行时依赖。
- 每张原图包含上下两个省份，文件名顺序对应上、下区域。
- 输出资源必须进入仓库，并能被 Vite 静态路径稳定加载。
- 白色标识必须是透明背景，不能保留浅色矩形边缘。

## 方案比较

### 已选：34 张预处理透明 PNG

用确定性的图像处理流程裁切上下区域、按亮度生成透明度并把文字转成白色。输出到 `public/images/province-labels/`，由轮播数据逐省映射。优点是加载稳定、显示清晰、响应式样式简单；代价是仓库增加 34 个资源文件。

### 未选：浏览器运行时裁切与抠图

页面加载 17 张原图后使用 Canvas 动态裁切、去背景和反色。资源数量更少，但首屏处理更重，容易闪烁，且浏览器兼容与测试成本更高。

## 实现设计

1. 使用固定、可复现的离线处理流程读取 17 张源 PNG。
2. 按文件名中的省份顺序分别裁切上、下区域；排除四周黑边和中间分隔带。
3. 根据像素亮度生成 alpha：浅色网格趋于完全透明，黑色毛笔字与拼音趋于不透明。
4. 将可见像素统一输出为白色，并保留抗锯齿边缘。
5. 以中文省份名命名 34 张输出文件，例如 `云南.png`、`台湾.png`。
6. 在 `TravelSlide` 数据中增加手写标识路径，现有英文 `location` 继续用于无障碍标签和数据属性。
7. `location-lockup` 移除两位编号和英文 `<h2>`，仅显示手写 PNG；图片设置合理的最大宽度、高度和 `object-fit: contain`。
8. 窄屏下缩小标识尺寸并保持左下安全边距；右下计数器布局不变。

## 错误处理

- 手写资源加载失败时回退显示现有英文省名，避免轮播缺少地点信息。
- 生成阶段校验输出恰好为 34 张，并检查每个轮播省份都有对应文件。

## 验收标准

- 34 个轮播省份均显示正确的白色毛笔字与拼音。
- 背景透明，无粉色网格、黑边或分隔带残留。
- 左下两位编号和原英文省名均不再显示，只保留手写标识。
- 桌面端和小于 880px 的布局均无遮挡、无溢出。
- 手写资源失败时英文回退生效。
- 现有轮播动画、随机顺序和认证相关测试不回归。
